# j3-elo-simulator
J3順位シュミレーターELO版

## 公式結果のメール通知

公式結果に試合の追加・得点訂正があり、GitHubへの保存が成功すると、指定した通知先へGmailから通知します。通知先未指定の場合は送信元自身へ送ります。変更なし・メタデータのみの更新では通知しません。端末画面への反映完了を確認する通知ではありません。

GitHubの Settings → Secrets and variables → Actions に次の Repository secrets を登録します。メールアドレス・認証情報はコードに記載しません。

| Secret | 値 |
| --- | --- |
| `J3_SMTP_USERNAME` | 送信元のGmailアドレス |
| `J3_SMTP_PASSWORD` | この通知専用のGoogleアプリパスワード |
| `J3_NOTIFICATION_EMAIL` | 通知先メールアドレス（任意。iCloudなどGmail以外も可） |

Googleアプリパスワードは2段階認証が必要です。通常のGoogleログインパスワードは使用しません。作成・利用条件は https://support.google.com/accounts/answer/185833?hl=ja を参照してください。

登録後、Actions → Automatic official J3 results → Run workflow で `test_email` をオンにして動作確認できます。実際の公式結果を確認・更新した後、テストメールを1通送信します。

認証設定がなければ警告を出して通知をスキップします。送信失敗でも公式結果更新は保持し、メールのみの自動再送はしません。送信失敗はワークフローの通知ステップで確認してください。SMTPサーバーの受付成功は受信箱への到着保証ではありません。

## 端末での更新確認

メールと両画面に「結果ID」を表示します。これは試合結果一覧から作る照合用IDで、セキュリティ用の署名ではありません。順序だけの変更では変わらず、得点訂正でも変わります。

両画面の「公式結果を更新」を押すと、取得APIがJリーグ公式サイトの終了済み試合を再取得し、検証して保存します。両画面は同じAPIの結果を使用します。「反映確認完了」は、取得・保存後の画面集計がその結果と一致した場合だけ表示します。試し入力中は実際の結果との一致を完了扱いにしません。

表示中は約5分ごとに確認し、公式サイトの最終確認から5分以上経過していれば再取得します。全利用者共通で取得間隔を最低60秒空け、更新中は同時取得を防ぎます。失敗・不完全なデータでは直前の正常な結果を保持します。自動確認時にAPIが利用できない場合はGitHubの保存済み結果を表示し、接続失敗を明示します。

「公式サイト確認」「結果データ更新」「画面取得」を分けて表示します。変更がなくても公式サイト確認時刻は進みます。APIへの接続先は `official-api-config.js` です。設定と共有コードを変更した場合、両HTMLの `?v=` を各ファイルのSHA-256先頭12桁に更新してください。

取得APIは別途Sitesに配備します。公開アクセスと本番接続が完了するまで、この変更は本番へ取り込みません。認証情報はブラウザーに配置しません。POSTは固定の公式取得処理のみで、スコアや取得URLを入力できません。

メール通知とGitHubへの保存は従来のActions（毎時17・47分の予定）で継続します。今回のボタン操作によるAPI保存ではメールは送信しません。Actionsには実行遅延があり、APIとメールが一時的に異なる結果IDになる場合があります。画面を閉じている間のAPI取得を保証する仕組みではありません。
