# j3-elo-simulator
J3順位シュミレーターELO版

## 公式データの自動更新と通知

公式結果のGmail・SMTP通知は停止しています。自動更新ワークフローにはメール送信ステップがありません。GitHub Actions自身の失敗通知は別の通知です。

検査はmainへの反映時とmain向けプルリクエストで実行します。開発用ブランチへ保存するだけでは実行しません。同じブランチの古い検査は、新しい検査が始まると中止します。手動検査も可能です。

公式結果・日程の取得は毎時17・47分の予定で継続します。取得プログラムの変更時も、mainへの反映後に実行します。取得・保存の前に、収集・検証・公開処理のテストを通します。

日程・ホーム／アウェー・開催状態に変更があれば直ちに保存します。変更がない場合は、確認時刻だけの保存・再公開を1時間以内に繰り返しません。これにより、不要なコミットと公開処理を抑えつつ確認時刻を更新します。

## 端末での更新確認

両画面に「結果ID」を表示します。これは試合結果一覧から作る照合用IDで、セキュリティ用の署名ではありません。順序だけの変更では変わらず、得点訂正でも変わります。

両画面の「公式結果を更新」を押すと、取得APIがJリーグ公式サイトの終了済み試合を再取得し、検証して保存します。両画面は同じAPIの結果を使用します。「反映確認完了」は、取得・保存後の画面集計がその結果と一致した場合だけ表示します。試し入力中は実際の結果との一致を完了扱いにしません。

表示中は約5分ごとに確認し、公式サイトの最終確認から5分以上経過していれば再取得します。全利用者共通で取得間隔を最低60秒空け、更新中は同時取得を防ぎます。失敗・不完全なデータでは直前の正常な結果を保持します。自動確認時にAPIが利用できない場合はGitHubの保存済み結果を表示し、接続失敗を明示します。

「公式サイト確認」「結果データ更新」「画面取得」を分けて表示します。変更がなくても公式サイト確認時刻は進みます。APIへの接続先は `official-api-config.js` です。設定と共有コードを変更した場合、両HTMLの `?v=` を各ファイルのSHA-256先頭12桁に更新してください。

正常に取得した公式結果は端末にも保存します。通信できない状態で再読み込みしても、その結果を表示しますが、新しい通信確認が完了したとは表示しません。端末の保存が禁止・容量不足の場合は通信で取得した結果の表示を継続します。別タブで取得した新しい結果も共有し、更新日時が古い結果で得点訂正を上書きしません。公式結果と試し入力は別々に扱います。

取得APIは別途Sitesに配備します。公開アクセスと本番接続が完了するまで、この変更は本番へ取り込みません。認証情報はブラウザーに配置しません。POSTは固定の公式取得処理のみで、スコアや取得URLを入力できません。

GitHubへの保存はActionsで継続し、メールは送信しません。Actionsには実行遅延があり、APIと保存済み結果が一時的に異なる結果IDになる場合があります。画面を閉じている間のAPI取得を保証する仕組みではありません。

自動保存中に別のサイト修正が公開された場合は、最新のmainへ結果コミットを載せ直して最大3回まで保存を試みます。得点データ自体の競合は自動解決せず、既存の公開結果を保護して処理を停止します。権限拒否時も直ちに停止し、強制上書きは行いません。未来日付の試合は確定結果として保存しません。

日程はGitHubの最新公開データを取得します。画面表示中の5分ごとの確認に加え、フォーカス・ページ復元・非表示からの復帰でも再確認します。通信に失敗した場合は直前の日程を保持し、失敗表示を出します。未来の更新時刻や未来の確定結果、日付とIDの不一致は反映しません。

## 非公開実用版の修正（2026-10-15）

- 遅いタブの応答を保存する直前にも新しい保存内容を再照合し、得点訂正や中止状態の巻き戻りを防ぎます。フォーカス復帰・別タブ更新時は、ネットワーク確認の待ち時間中でも端末内の新しい公式結果を先に画面へ反映します。保存削除・全消去では直前の公式実績を保持し、通信確認済みの表示を解除します。旧手入力や試し入力は公式実績に入りません。
- 公式日程を端末へ保存し、別タブと復帰時に再読込します。日程の一部欠落でも未完了カードを保持し、中止・延期を優先します。未来の終了状態は拒否します。更新サービスが403等で利用できない場合、更新ボタンもGitHub保存済みの公式結果を取得します。この場合、公式サイトを今確認したとは表示しません。
- `python scripts/build-private-site.py` で非公開配備用の `dist/` を作成します。最新の検証済み公式結果を初期表示へ同梱し、通信待ちで古い9試合表示に戻ることを防ぎます。最新日程を取得できない初回は同梱日程を使用し、再取得失敗を明示します。非公開設定は配備先のアクセス制御で行います。

計算式・配色は維持します。現行の勝敗確率はElo＋Davidson方式（K=20、ホーム補正+60）で、未消化試合の順位計算には代表スコアを使用します。`poisson()` は現行コードで呼ばれておらず、EloとPoissonを混合した予測モデルではありません。

検査：`node tests/regression.cjs`、`node tests/result-sync.test.cjs`、`node --test tests/feed-resilience.test.cjs tests/next-fixture.test.cjs`、`python -m unittest discover -s tests -p 'test_*.py'`。iPadの復帰・別タブ・削除などのイベントと画面集計をJavaScript実行環境で再現します。実際のSafari/iPadの描画・操作確認は別途必要です。
